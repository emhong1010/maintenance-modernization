# 아키텍처 — 차량 정비 이력 시스템 (legacy)

## 1. 명령 → 함수 → DB 테이블

```
 [ 명령 ]              [ 함수 ]                    [ DB 테이블 ]

 history ──────────▶ get_history ──── 읽기 ────▶ ┌──────────┐
                                                 │ records  │
 add ──────────────▶ add_record ───── 읽기 ──┐   │ (정비이력)│
                                     쓰기 ──┼──▶ └──────────┘
                                             │   ┌──────────┐
                                             └─▶ │ vehicles │ ◀── 읽기 ── admin (전체 출력!)
                                                 │ (차량·고객)│
 recall ───────────▶ find_recall_targets ─┐      └──────────┘
                                          ├ 읽기 ▶ recalls · vehicles · records
 status ───────────▶ recall_status ───────┘      (같은 로직을 복사해서 사용)

 report ───────────▶ monthly_report ───── 읽기 ──▶ records

 모든 함수 ──▶ conn() ── sqlite3.connect(MAINT_DB)   ※ 연결을 닫지 않음
```

## 2. 함수별 테이블 사용

| 함수 | vehicles | records | recalls | 비고 |
|---|---|---|---|---|
| `add_record` | 읽기 (존재 확인) | **쓰기** | — | 디버그 출력에 고객 이름·전화번호 |
| `get_history` | — | 읽기 | — | 정비일 최신순 |
| `find_recall_targets` | 읽기 | 읽기 (조치 여부) | 읽기 | 차량마다 쿼리 반복 (N+1) |
| `recall_status` | 읽기 | 읽기 | 읽기 | `find_recall_targets`를 복사한 코드 |
| `monthly_report` | — | 읽기 | — | `LIKE '2024-03%'` 로 월 필터 |
| `main` → `admin` | 읽기 (전체) | — | — | 하드코딩 비밀번호로 고객 정보 전체 출력 |

## 3. 처음 보는 사람이 알아야 할 위험 3가지

1. **SQL 인젝션** — 모든 SQL을 문자열을 이어 붙여 만든다. 차량번호나 리콜 코드 하나로 쿼리를 조작할 수 있다.
2. **개인정보 노출** — `add_record`의 디버그 출력과 `admin` 명령이 고객 이름·전화번호를 그대로 출력한다. 관리자 비밀번호도 코드에 적혀 있다.
3. **중복 로직** — 리콜 대상 판별 로직이 두 함수에 복사되어 있다. 한쪽만 고치면 두 결과가 조용히 달라진다.

## 4. 지켜야 할 현재 동작 (특성 테스트가 고정)

- 리콜 기간 경계일(시작일·종료일)에 생산된 차량도 대상에 포함
- 조치율은 반올림하지 않고 버림 (2/3 → 66)
- 없는 차량 등록 → `-1`, 주행거리 오류 → `0`, 음수 비용 → `0`
- 없는 리콜 코드 → `find_recall_targets`는 `[]`, `recall_status`는 `None`
